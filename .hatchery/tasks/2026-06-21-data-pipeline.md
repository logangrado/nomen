## Objective

Implement Phase 1 of the Nomen data pipeline as described in `docs/architecture.md`:
PostgreSQL infrastructure, SQLAlchemy Core schema, Alembic migrations, and the SSA ETL pipeline.

## Context

Greenfield project — only `README.md` and `docs/architecture.md` existed at start. The ADR
specified PostgreSQL (not DuckDB), SQLAlchemy Core (not ORM), Alembic for migrations, and
psycopg3 COPY for bulk loading. First data source is SSA (US national + state name frequency).

### Key decisions

**Migration written by hand** (not autogenerated): `alembic revision --autogenerate` requires a
live DB and an installed package. The hand-written migration is equivalent and was reviewed against
`schema.py`. Future schema changes should use `inv migration --msg '...'`.

**Two-pass SSA loader** to avoid loading 7M rows into RAM:
1. Stream both zips → collect `set[str]` of ~100K unique names
2. `executemany` ON CONFLICT for `names`; then COPY stream for `name_stats`

**`executemany` for `names`, COPY for `name_stats`**: PostgreSQL COPY does not support
`ON CONFLICT`, so name deduplication uses `executemany`. COPY is reserved for the high-volume
`name_stats` table where duplicate PKs are not a concern.

**Re-run safety**: `load_ssa` does `DELETE FROM name_stats WHERE source = 'SSA'` before each
COPY run. Keeps the pipeline idempotent without needing a unique constraint on `name_stats`.

**`invoke` instead of `Makefile`**: `invoke` was already in dev deps; `tasks.py` provides
equivalent targets.

### Typical dev workflow

```bash
inv up           # start Postgres
inv migrate      # apply alembic migrations
inv ingest-ssa   # download + load ~7M SSA rows (takes a few minutes)
inv test         # run test suite (requires pytest-postgresql)
```

### Gotchas for future agents

- `alembic/env.py` imports from `nomen.db.schema` — the package must be installed (`uv sync`)
  before running `alembic` commands.
- The `data/` directory is gitignored. `data/ssa/.gitkeep` was created but is not tracked.
- CHECK constraints on `gender`, `rating`, `region_type` are in `schema.py` but Alembic
  autogenerate has limited CHECK comparison support — review any future autogenerated migrations
  to ensure CHECK constraints are not dropped.
- `name_stats` has no uniqueness constraint beyond the serial PK — a re-run without the
  `DELETE` guard would silently accumulate duplicate rows.
