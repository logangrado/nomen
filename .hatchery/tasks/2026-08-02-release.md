## Objective

Prepare nomen for beta release:

## Context

Nomen is a Python/FastAPI app (uv-managed, PostgreSQL backend). No CI or deployment artifacts
existed. Patterns were borrowed from `seekr-hatchery` (`/Users/grado/Code/tools/seekr-hatchery`),
which uses the same uv + conventional-commits versioning stack.

## Summary

### Key decisions

**Conventional commits → semver** (from seekr-hatchery pattern):
- `feat:` → minor bump, `fix:|perf:|refactor:` → patch, `type!:` → major, `no-bump:` → skip
- The release workflow fires on every push to `main` and looks up the associated PR's commits to
  determine the bump. Direct pushes to main (no PR) are silently skipped.

**Docker image**: published to `ghcr.io/logangrado/nomen` using `GITHUB_TOKEN` — no extra secrets
needed. The Docker workflow triggers on `v*.*.*` tags emitted by the release workflow.

**`nomen init` CLI command** added to `src/nomen/cli.py`:
- Chains: `alembic upgrade head` → `load_ssa()` → `load_btn()` → `load_popularity()`
- All three pipeline functions are idempotent (SSA: delete+reload, BTN: ON CONFLICT DO UPDATE,
  popularity: delete+recompute), so `nomen init` is safe to re-run.

**docker-compose init service** (profile `init`):
- `docker compose up -d` → starts postgres + web
- `docker compose run --rm init` → populates database

**Helm init Job** is a `post-install,post-upgrade` hook with `before-hook-creation` delete policy.
Set `init.enabled=true` to run it on a given upgrade; omit it for normal rollouts. The hook
re-runs on every upgrade where the flag is set (old Job is deleted first).

### Gotchas for future agents

- The CI test job uses ubuntu-latest which ships postgres binaries; `pytest-postgresql` finds them
  automatically. No service container is needed.
- The `alembic.ini` uses a relative path for `script_location`. The Dockerfile copies it to `/app/`
  and the `nomen init` command (and the container's working directory) must be `/app/` for Alembic
  to resolve it correctly. The default `WORKDIR /app` in the Dockerfile handles this.
- `ghcr.io/logangrado/nomen:buildcache` is used as a layer cache registry ref. It is created
  automatically on first push; no manual setup needed.
- The Helm chart does not bundle a postgres deployment — it expects an external DATABASE_URL
  (e.g., a k8s Secret `nomen-db`). For homelab, deploy postgres separately or use a managed DB.
